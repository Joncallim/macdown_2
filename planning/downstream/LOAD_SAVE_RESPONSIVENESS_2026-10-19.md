# Keep document loading and save recovery responsive

## Owner outcome and current evidence

Opening an automatically detected UTF-16 file must not block the UI during its detection scan or steal focus from a newer open request. Folder setup should not immediately repeat its completed workspace scan on activation. Save-conflict recovery should perform file reads, decoding and hashing away from the UI while preserving current edits and save ownership.

These are concrete source-derived defects in existing paths, not a measured explanation of every slow load or save. The 1 MB parser benchmark does not measure file-open latency. Preferences preservation is a separate correction recorded under #53.

Baseline: master `4aa46bfa6b91bf1c1d218b9b1f67480312f66396`; this branch starts at settings correction `91e62f8f` and retains the integration staging history. Independent source review confirmed the three areas below. Existing E18 file fidelity, E22 index/search authority, release-hardening and epic-standard contracts remain binding. No new dependency, file permission, preview authority, format guess, highlighting cutoff or publishing authority is introduced.

## Slice 1: automatic encoding detection

Allocate the open-request generation once at public entry. A private helper carries that identity through the existing single automatic-encoding retry. The synchronous detector's complete read and scan runs inside a detached user-initiated task, just as the existing document load does. Explicit encoding skips automatic detection. Real read/decode errors remain errors. Every suspension before publication is followed by the existing duplicate-tab admission check. An older request may finish opening its own tab, but cannot activate it over a newer open.

The only new internal seam is an optional Sendable callback immediately before detached detection, used to hold that real operation in tests. Production leaves it unset. Tests hold A at detection, complete B on the main actor, and then release A. Both the UTF-8-with-NUL and failed-UTF-8 branches must preserve B's focus and decode A correctly. Additional controls cover explicit encoding and a second open of A completing before the original detection returns. Fixtures use private temporary files and recovery stores.

This slice removes the loaded-text NUL trigger scan from the main actor and fixes the retry identity error. The trigger scan now runs alongside the detached document load; explicit encoding continues to skip automatic detection. It does not eliminate repeated reads, change native-window publication timing, or claim a measured end-to-end loading improvement. Completion requires regressions, strict checks, independent review and final combined-candidate validation.

## Slice 2: workspace index freshness

Each `setFileTreeRoot` request advances a window-owned generation before its first suspension and invalidates the prior freshness record and tree-root-applied phase. Only a still-current request for an open window may publish after awaited tree/index work. A root change or close during either await retires the old request; the generation distinguishes A → B → A even when the URL returns to its earlier value. Refreshes wait until the current explicit request has applied its root to the file tree, then capture the actual access root. This allows a later accepted folder rename to remap that root without leaving a stale requested-root equality check in the refresh path. Clearing the root clears the index and search root only while that clear request remains current.

Record freshness after rebuild completion only when the newest invoked rebuild is still current and the index is `.ready`, and bind that record to both the root-request generation and access root. Activation's existing five-second throttle applies only to that same generation and root. A current failed refresh clears any earlier freshness because the failed index discards its paths; after access returns, activation must rebuild even inside the previous throttle interval. Superseded failures cannot clear a newer success. Explicit filesystem mutations still use the zero-interval refresh path. A root request records its pending search publication only after the file-tree model adopts that root. A refresh that completes while the root request is waiting cannot republish the previous folder scope; if it supersedes the initial same-root build, search publication waits until the current build reaches a terminal ready or failed state. The existing failed-root publication behavior is retained. A late completion from the older initial build cannot replace the newer completion's timestamp or publish search again.

The app test target injects the existing internal `WorkspaceFileIndex` walk seam through `WindowController`'s internal initializer. Tests count real walks, hold individually gated walks while roots switch or clear, exercise same-root activation supersession and late completion, a refresh during a paused root change, an accepted folder-root remap, and a failed build followed by a successful activation. Mutation tests wait for completed walks and published paths; fixtures use unique defaults suites and temporary session/root directories and close their real windows through the normal controller lifecycle. No package API or dependency changes are needed.

## Slice 3: save-conflict snapshot reads

Pass the original save context through conflict recovery. Require the latest save and its original document lifetime before starting and after an off-main read. A tab switch alone does not cancel it. Before applying any result, re-fetch the owning document and establish its baseline, encoding, pending revision and backing-state lineage; never overwrite newer local text with a captured value. Recheck ownership after recovery persistence.

Admission is baseline-compatible: last-known revision, restored baseline hash, pending external revision, backing state and encoding must still equal those captured before the read. Ordinary newer edits and edit/undo remain admissible when the live state is dirty or prompting-close; reconcile the returned disk snapshot against that live text and conditionally retry it, matching the existing behavior that reconciles current edits after the first write fails. A changed baseline, destination/lifetime or newer save makes the old result obsolete. A changed baseline is obsolete even when the user has typed after reloading; it must not overwrite the newer operation's error. Superseding reloads and state changes remain untouched. Failed reads likewise publish only while the original save/lifetime and compatible lineage remain relevant. After conflict recovery persistence, publish an unresolved-conflict error only if the reconciled snapshot still owns the current state.

Equal lineage values cannot distinguish every external-state sequence that returns to identical values (an ABA sequence). This bounded policy does not claim to identify exclusively local editing history; it preserves live text and conditional on-disk publication, and rejects directly observed changed-baseline reloads. It introduces no new external-state revision or automatic overwrite authority. Internal optional callbacks after the detached snapshot read and after recovery persistence allow deterministic tests to hold a read result or introduce a newer outcome before error publication; production leaves them unset. Preserve one metadata-only retry, encoding override, destination policy and conditional publication.

Tests must hold a real detached snapshot read and exercise typing, edit/undo, another tab, newer saves, external reload, close/reopen, and destination changes. Safe completion includes preservation of file bytes, live text, recovery and relevant errors. Broad preview-folder permission decisions are unrelated to these bounded corrections.
