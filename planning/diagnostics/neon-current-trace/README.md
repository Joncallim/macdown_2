The bundled observer binds the test helper to the package-test executable and filters crash reports to that identity. The two startup cases are observed alongside the two existing idle-restore cases. The trace correlates immutable client/query identity, named ranges, token applications, TextKit attribute writes and rendered signatures. The original assertion order, clocks, idle delay, 8,192 UTF-16 production fallback and dependency pins remain intact. A passing instrumented case is inconclusive about an earlier failing schedule.

The cleanup test adds observation-only timestamps for cancellation callback entry/exit and a Dispatch timer callback on a separate queue. That timer never participates in the cleanup gate. Both are compared with the existing Swift watchdog timeline; the 25 ms deadline and 150 ms assertions are unchanged. A late Dispatch callback cannot distinguish kernel timer delivery from dispatch-queue scheduling on its own. The separate local diagnostic run recorded Dispatch callback and Swift watchdog return around 27–35 ms, with the blocking cancellation callback ending around 210 ms; both startup cases passed locally. These readings validate the recorder only, not the hosted cause.
